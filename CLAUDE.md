# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Paperwork is an Expo React Native app whose sole purpose is to be a **test target for mobile agents and app crawlers** (Appium / Kobiton). It has no backend — all state is seeded in memory and resets on every reload — so flows run without accounts, network, or payment setup. The point is realistic multi-screen navigation, not real functionality.

`GUIDELINES.md` is the source of truth for the screen map, the critical agent flows, and the exact `testID`s each flow relies on. Treat those test IDs as a public contract: changing or removing one breaks the agent test suites that target this app. `CRAWLER.md` is the scoring rubric for crawler runs; `crawler-expected-graph.json` is the machine-readable ground truth, regenerated by `yarn graph` and guarded by `yarn check-graph`.

## Commands

Package manager is **yarn** (`packageManager: yarn@1.22.22`).

- `yarn install` — install deps
- `yarn start` / `yarn ios` / `yarn android` / `yarn web` — Metro dev server / run on a target

**Node 22 is required** (`.nvmrc` → `22.22.0`); Expo's local port scanner fails on Node 25. Run `nvm use` first.

If Metro dies with `EMFILE: too many open files`, raise the limit before starting: `ulimit -n 65536 && yarn start`.

### Checks

There is still **no test framework and no linter** — don't invent `yarn test`/`yarn lint`. There are, however, plain-node check scripts; run all three after any change:

- `yarn selfcheck` — pure-logic asserts over navcore, validate, data, and graph (`scripts/*.test.js`)
- `yarn check-graph` — App.js's `ROUTES` map, `ROUTE_META`, and the committed `crawler-expected-graph.json` must agree; fails on a stale JSON (regenerate with `yarn graph`)
- `yarn bundle-check` — Metro bundles both platforms; catches every broken import (~15 s)

Optional: `yarn render-check` (renders every route under `react-test-renderer` if it can resolve it; exits 0 with an explanation otherwise) and `yarn gen-docs` (regenerates the graph-derived sections of `GUIDELINES.md` and `CRAWLER.md`).

### Running on a physical device / for Appium

The Metro debug build does **not** load on a physical Android device here — RN's new-architecture ReactHost falls back to `loadJSBundleFromAssets` and red-boxes with "Unable to load script". Build a **standalone release APK** instead, which embeds the JS bundle and needs no Metro:

```sh
yarn android --variant release
```

Release is signed with the debug keystore (see `android/app/build.gradle` `signingConfigs`), so the output `android/app/build/outputs/apk/release/app-release.apk` is directly installable and uploadable to Kobiton. Appium caps: `appPackage=com.d4rkwinz.paperwork`, `appActivity=com.d4rkwinz.paperwork.MainActivity`.

The JS entry is `index.js` → `import 'expo/AppEntry'`; the native build resolves the bundle through `index`, so this file must exist (package.json `main` alone is not enough for the native build).

This is a **bare** project: `app.json`'s `version` does not reach the native build. When bumping the app version, also bump `versionCode`/`versionName` in `android/app/build.gradle` or the installed APK will report the old version.

## Architecture

Since v1.1.0 the app is **`App.js` plus `src/`** — `App.js` (~200 lines) holds the shell (route table, top bar, tab bar, hardware back), and `src/` holds everything else. There is still no router library, no Context/Redux, no AsyncStorage.

- **Navigation is hand-rolled.** Stack helpers live in `src/navcore.js`; `App()` holds the `stack` in `useState` and exposes `nav` = `push` / `replace` / `back` / `root`. The current route is `stack[stack.length - 1]`, and `App()` renders it via the keyed **`ROUTES` map** (`const Screen = ROUTES[route.name] || NotFound`) — not a chain of `route.name === "X" && ...`. Every screen receives the uniform `({ nav, params, app })` props, rendered with `key={route.key}` so screens remount per push.
- **Adding a screen** = add a `*Screen` component under `src/screens/`, one entry in `App.js`'s `ROUTES`, one `ROUTE_META` entry in `src/data.js` (name, tier, addressing, anchors, tab, instances, edges, trap/escape), then `yarn graph && yarn gen-docs` and commit the regenerated files. `yarn check-graph` fails until all three agree.
- **All state lives in `App()`** (`requests`, `profile`, `paymentMethods`, `session`) and is threaded down via the `app` prop.
- **Seed data is `src/data.js`** — eight seeded collections (`SERVICES`, `INITIAL_REQUESTS`, `DOCUMENTS`, `INVOICES`, `NOTIFICATIONS`, `POLICIES`, `PROVIDERS`, `REMINDERS`) plus `ROUTE_META`. Seeded IDs (e.g. `REQ-1042`) are stable across launches; newly booked requests get a random `REQ-####`, newly saved cards a random `pm-####`.
- **`testID` convention** is generated, not hand-typed: `` `${prefix}-${slug(value)}` `` where `slug()` (`src/slug.js`) lowercases and dashes non-alphanumerics (so `"8:00 AM"` → `time-8-00-am`, `"Office - 9 Market Plaza"` → `select-address-office-9-market-plaza`). Reusable controls (`ChoiceRow`, `Tab`, `PrimaryButton`, etc. in `src/ui.js`) derive their `testID` this way. When you add options, the IDs change deterministically with the label — keep labels stable so agent suites keep matching.
- **Styling** is `src/styles.js`; the palette is a warm-paper light theme. `ANDROID_NAV_BAR_GAP_ANDROID` / `TAB_BAR_HEIGHT` offset content above the fixed bottom tab bar.

### The tier-split addressing rule (do not violate)

Routes are tiered in `ROUTE_META`: `v1` and Tier `A` are **exhaustively addressed** (every interactive element carries a `testID`), Tier `B` (the generic renderers in `src/screens/generic.js` + `src/screens/Bulk.js`) is **deliberately sparse** — only `${testPrefix}-primary` and `${testPrefix}-list` carry testIDs; rows, inputs, and secondary buttons carry only `accessibilityLabel`. This split is the fixture's measurement: Tier A scores crawler intelligence on exact testIDs, Tier B scores scale on label/text/vision navigation. **Adding row or input testIDs to a Tier B renderer silently turns the scale tier into a second intelligence tier and invalidates the two-score rubric** — the single most likely mistake a future edit can make. Conversely, don't strip testIDs from Tier A/v1 screens: they're the public contract.

## Constraints

This dependency-light shape is deliberate: no backend and no native-only modules so the same Expo project runs identically on iOS and Android for cross-platform agent testing. Preserve that — **don't add a backend, a navigation library, or a platform-specific module** unless explicitly asked. Don't add new dependencies for the check scripts either; they run under plain node.
